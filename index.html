What the words mean

Four terms the rest of the site takes for granted.

A reader

A book-length Quarto text for one course, written as chapters in the repository and rendered to HTML. Not a set of lecture notes — it is meant to be read on its own.

the readers →

The joint reader

The spine across both authors' books. It fixes shared notation, says what a topic is for, and points at the chapters that develop it. It links, it never copies — a duplicated chapter starts drifting immediately.

the spine →

The decks

Reveal.js lectures written in Quarto, one per week, drawing on the same datasets and the same stylesheet as the readers. Rendered from source, never committed as HTML.

all decks →

The data

One canonical folder, loaded with here::here() from anywhere in the repo. Every dataset carries a provenance line and a citation — the site schema requires both, so an undocumented dataset fails the build rather than passing quietly.

How this is organized

One rule holds the layout together, and it is about people rather than code.

Each author owns a directory outright. Nothing under one author's reader is edited by the other; the joint reader and everything shared change by pull request. This is recorded in .github/CODEOWNERS and mirrored in the owner field of every entry on this site. It exists so that two people can write a methods book across a semester without spending that semester resolving merge conflicts in each other's prose — git cannot help you with prose, so every conflict becomes a judgement call about someone else's argument.

The three build paths — readers, decks, site — are deliberately independent. None requires the others to have run, so a typo on a web page never needs R and Quarto, and writing a chapter never needs Node. See CONTRIBUTING for the full workflow, 4 tutorials for setup and rendering, and and AI.md in the repository for how these materials are and are not written.
